# Быстрый старт (AmneziaWG 3.1)

Минимальные шаги для ветки **`amnezia-wg-docker-v01`** (образ `myceliummesh/amneziawg-ui:3.1`).

Разбор ошибок и опыт настройки — в конце этого файла и в разделе **«Что мы выяснили»** в **[README.md](README.md)**.

## 1. Окружение

```bash
cd /путь/к/amnezia-wg-docker
git checkout amnezia-wg-docker-v01
cp .env.example .env
```

Если рядом лежат данные от **AWG 2.0**, переименуйте каталог — том 2.0 с этим образом **несовместим**:

```bash
mv awg-data awg-data-v2-backup   # если был
```

Старый `.env` от ветки `main` (с `WG_HOST`, `PASSWORD_HASH`, `JC`/`I1`…) тоже не подходит: для 3.1 нужны `WEB_UI_*` и `DEFAULT_*` из `.env.example`.

## 2. Обязательные переменные

| Переменная | Что указать |
|------------|-------------|
| `WEB_UI_PASSWORD` | **base64(SHA-256(пароль))** для входа в панель, не открытый пароль. |
| `WEB_UI_USER` | Логин (по умолчанию `admin`). |
| `DEFAULT_PORT` | UDP-порт VPN (в шаблоне `443`; **должен совпасть** с пробросом в `docker-compose.yml` и с портом сервера в UI). |

### Сгенерировать WEB_UI_PASSWORD

```bash
printf 'ваш-пароль' | openssl dgst -binary -sha256 | base64
```

Вставьте вывод в `.env` как `WEB_UI_PASSWORD=...`.

В шаблоне лежит хэш от пароля **`changeme`** — смените его.

## 3. DNS и фаервол

- **DNS A-запись** (если используете имя) → IP сервера с Docker.
- **UDP `DEFAULT_PORT`** — открыть клиентам (роутер/фаервол). Пример: `443/udp`.
- **TCP `WEB_UI_PORT`** — в compose только на `127.0.0.1`, наружу не открывать.

## 4. Запуск

```bash
docker compose pull
docker compose up -d
docker compose ps
```

Ожидаемо: VPN слушает снаружи на UDP `DEFAULT_PORT`, UI — `127.0.0.1:WEB_UI_PORT` (часто `54845`).

Пример здорового `docker ps`: `0.0.0.0:443->443/udp` и `127.0.0.1:54845->54845/tcp`, статус `healthy`.

## 5. Веб-интерфейс через SSH

```bash
ssh -f -N -L 54845:127.0.0.1:54845 пользователь@vpn.example.com
```

В браузере на своём ПК: `http://127.0.0.1:54845`  
Логин/пароль — из `.env` (`WEB_UI_USER` + исходный пароль, из которого сделали хэш).

Если в `.env` другой `WEB_UI_PORT`, подставьте его в `-L` и в URL.

## 6. Первый сервер в UI

В форме **«Создать новый VPN-сервер»**:

1. **Имя** — любое (`vpn`, `raistlin`, …).
2. **Порт** — **тот же**, что `DEFAULT_PORT` и проброс Docker.  
   Если в `.env` стоит `443`, а форма предлагает `54844` — **исправьте на `443`**, иначе клиенты не достучатся.
3. **Расширенные настройки** — для первого запуска можно не включать: подсеть, MTU, DNS, endpoint и обфускация 3.1 (header protection, random trailers и т.д.) генерируются сами.
4. **Создать сервер** → убедиться, что сервер **запущен** (в шапке UI не «0/0»).

## 7. Клиент в UI

1. **Имя клиента** — любое.
2. **Allowed IPs** — по умолчанию `0.0.0.0/0, ::/0` (весь трафик через VPN).
3. Галочка **«Применить I-настройки (I1–I5)»** — можно оставить включённой.
4. **I1–I5** — для обычной работы **оставьте пустыми**: подставится значение сервера (часто QUIC-подобная сигнатура в `I1`).  
   Пустые `I2`–`I5` = эти пакеты не шлются (в отличие от старого образа 2.0, который мог подставить случайный hex).
5. **Добавить** → скачать `.conf` / QR.

Клиент: **AmneziaVPN ≥ 5.0.1.5** (или совместимый AWG 3.1). Профили **2.0 и обычный WireGuard не подойдут** — нужны новые конфиги с этого сервера.

Скрипт `seed-clients.sh` от стека 2.0 (API awg-easy) **с этой панелью не совместим**.

### Маскировка под DNS (по желанию)

В поле **I1** при создании клиента (не в старый `.env` от 2.0):

```text
<r 2><b 0x8580000100010000000004796162730679616e6465780272750000010001c00c000100010000026d000457fa27d1>
```

`I2`–`I5` оставьте пустыми. Это только предварительный пакет перед handshake; порт по-прежнему задаётся сервером (часто UDP 443).

После выдачи клиента проверьте в `.conf` / в профиле AmneziaVPN, что `I1` именно такой — иначе в трафике будет дефолт сервера или старый случайный hex от профиля 2.0.

## 8. Keenetic (Giga и др.)

### KeeneticOS 5.2+ (проверено)

После обновления до **5.2** конфиг AmneziaWG **3.1** с этой панели импортируется штатно, туннель поднимается:

1. **Управление → Настройки системы → Изменить набор компонентов** → **WireGuard VPN**.
2. **Интернет → Другие подключения → Загрузить из файла** → `.conf` клиента с панели 3.1.
3. При необходимости включите использование для выхода в интернет / политику приоритета подключений.

Конфиг 3.1 **нельзя** превратить в 2.0 правкой файла — handshake не сойдётся.

### KeeneticOS 5.1.x и старше

На стабильном **5.1.x** нативно обычно только AmneziaWG **2.0**: штатный импорт `.conf` 3.1 не работает.

Варианты:

- обновиться до **5.2+** (предпочтительнее, если доступно);
- либо Entware + [AWG Manager](https://awgm.hoaxisr.ru/install/) в режиме **Kernel** (нужна USB/ext4, компонент OPKG).

## 9. Проверка

На сервере:

```bash
docker compose ps
docker compose logs -f
docker exec awg-with-ui awg show
```

На клиенте (Linux, после подключения):

```bash
ip -4 addr show amn0
ping -c 3 10.12.14.1    # шлюз VPN — подсеть из DEFAULT_SUBNET / UI
ping -c 3 1.1.1.1
curl -4 -fsS --max-time 8 https://ifconfig.me/ip
```

Ожидаемо: `amn0` UP, пинги ок, внешний IP = IP VPN-сервера. Есть `latest handshake` в `awg show` — параметры сошлись.

Нет handshake: порт/фаервол, клиент без AWG 3.1, старый профиль 2.0, или на Keenetic прошивка без 3.1.

## Типичные грабли (кратко)

1. Оставили `.env` / `awg-data` от ветки **2.0** — панель 3.1 не поднимется как надо.
2. В UI создали сервер на порту **54844**, а Docker пробросил **443** — снаружи тишина.
3. Открыли UI с внешнего IP — он слушает только localhost; нужен SSH `-L`.
4. Прописали DNS-сигнатуру в старый `.env` 2.0 и ждали маскировку — в живом профиле клиента остался random hex; I1 задаётся **при создании клиента** в UI 3.1.
5. Подключили старый профиль Amnezia («Server 1/2» от 2.0) к серверу 3.1 — не подойдёт.
6. На Keenetic **5.1** импортировали `.conf` 3.1 — не взлетело; на **5.2** — заработало.
