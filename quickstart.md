# Быстрый старт

Минимальные шаги, чтобы поднять сервер AmneziaWG с веб-панелью.

## 1. Окружение

```bash
cd /путь/к/amnezia-wg
cp .env.example .env
```

Откройте `.env` в редакторе.

## 2. Обязательные переменные

| Переменная | Что указать |
|------------|-------------|
| `WG_HOST` | Публичный **IP** или **DNS** (то, что клиенты увидят как Endpoint). Не используйте `127.0.0.1` для реальных клиентов из интернета. |
| `PASSWORD_HASH` | Bcrypt-хэш пароля веб-панели (не сам пароль). |

В `.env` каждый символ **`$` в хэше удваивайте** (`$$`), иначе Docker Compose испортит строку.

### Сгенерировать хэш пароля

Надёжный вариант (пароль передаётся через переменную окружения, без вставки в кавычки в Node):

```bash
export PASS='ваш_пароль'
docker run --rm -e PASS node:20-alpine sh -c \
  'mkdir -p /tmp/bc && cd /tmp/bc && npm install bcryptjs -q && node -e "console.log(require(\"bcryptjs\").hashSync(process.env.PASS, 12))"'
```

Скопируйте вывод, затем **удвойте все `$`** и вставьте в `.env` как `PASSWORD_HASH=...`.

Если в пароле есть символы вроде `\5`, не вставляйте пароль внутрь `node -e "..."` — только через `PASS`, как выше.

## 3. DNS и фаервол

- **DNS:** запись типа **A** для вашего имени должна указывать на IP сервера с Docker.
- **Порты** (значения по умолчанию из `.env.example`):  
  - **UDP** `WG_PORT` (часто `51820`) — VPN: должен быть доступен клиентам (**проброс на роутере / фаервол**).  
  - **TCP** `PORT` (веб-UI): в `docker-compose.yml` сервис слушает только **`127.0.0.1`** на сервере — **наружу не выставляется**. Отдельно открывать `PORT` в интернет не нужно (и не стоит).

## 4. Запуск

```bash
docker compose build
docker compose up -d
```

## 5. Веб-интерфейс через SSH (рекомендуется)

Панель не слушает на внешнем IP — только на **localhost** сервера. Зайти с своего ПК:

```bash
ssh -f -N -L 51821:127.0.0.1:51821 пользователь@vpn.example.com
```

`-f` — туннель уходит в **фон**, терминал не нужно держать открытым; остановить: найти процесс `ssh` с этим `-L` и завершить (или `pkill -f '51821:127.0.0.1:51821'`).

Если в `.env` другой `PORT`, подставьте его **дважды** (локальный порт и цель туннеля).

Пока туннель активен, в браузере на **своей машине**:

```text
http://127.0.0.1:51821
```

(или тот локальный порт, что указали в `-L` слева). Вход — **паролем** от `PASSWORD_HASH` (отдельного логина нет).

**С сервера по SSH** (без туннеля) панель тоже доступна: `http://127.0.0.1:PORT` прямо на хосте.

### Если всё же нужен веб-UI из интернета

В `docker-compose.yml` замените проброс TCP на форму без `127.0.0.1:` (как в старых примерах) и откройте `PORT` в фаерволе — это уже не «только SSH», осознанно решайте риски.

## 6. Клиенты по списку (по желанию)

1. Заполните `clients.txt`.
2. После запуска UI:

   ```bash
   chmod +x seed-clients.sh   # один раз, если нужно
   export ADMIN_PASSWORD='ваш_пароль_от_веб_UI'
   ./seed-clients.sh
   ```

- **На сервере** (по SSH): `HOST` по умолчанию `127.0.0.1` — подходит, веб-UI слушает только там.  
- **С вашего ПК** при активном SSH-туннеле `ssh -f -N -L 51821:127.0.0.1:51821 пользователь@vpn.example.com`:

  ```bash
  export HOST=127.0.0.1
  export PORT=51821
  ./seed-clients.sh
  ```

  (запускайте скрипт локально, пока туннель активен.)
