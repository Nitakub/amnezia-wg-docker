# AmneziaWG 2.0 + веб-интерфейс (Docker)

Локальная обвязка вокруг образа **[awg-2.0-with-ui](https://github.com/N-Rn00/awg-2.0-with-ui)**: AmneziaWG 2.0 и панель управления клиентами (на базе awg-easy). Сборка образа идёт из указанного репозитория; конфигурация сервера задаётся через `.env`.

## Быстрый старт

Пошаговая инструкция — в **[quickstart.md](quickstart.md)**.

## Требования

- **Docker** и **Docker Compose** (plugin `docker compose`).
- На хосте: возможность использовать **`/dev/net/tun`** и capabilities `NET_ADMIN`, `SYS_MODULE` (см. `docker-compose.yml`).
- **VPN (UDP):** снаружи должен быть доступен **`WG_HOST`** и порт **`WG_PORT`** (проброс на роутере/фаерволе).
- **Веб-UI (TCP):** по умолчанию слушает только **`127.0.0.1`** на сервере — в интернет не выставлен; доступ с ПК через **SSH port forwarding** (см. **[quickstart.md](quickstart.md)**).

## Структура репозитория

| Файл / каталог | Назначение |
|----------------|------------|
| `docker-compose.yml` | Сервис, сборка из GitHub, порты, том `awg-data` |
| `.env.example` | Шаблон переменных окружения (можно коммитить) |
| `.env` | Рабочие секреты и настройки (**в `.gitignore`, не коммитить**) |
| `awg-data/` | Ключи, `awg0.conf`, данные клиентов на хосте (**не коммитить**) |
| `clients.txt` | Имена клиентов для массового создания через API |
| `seed-clients.sh` | Создание клиентов из `clients.txt` после запуска UI |

## Конфигурация

1. Скопируйте шаблон: `cp .env.example .env`.
2. Заполните минимум **`WG_HOST`** (endpoint для клиентов) и **`PASSWORD_HASH`** (bcrypt для входа в веб-панель).
3. В файле `.env` для Docker Compose символ **`$` в bcrypt-хэше нужно удваивать** (`$` → `$$`), иначе Compose подставит «переменные» и сломает хэш. Подробности и примеры — в комментариях внутри `.env.example`.

Остальные переменные (порты, DNS, обфускация AmneziaWG и т.д.) описаны в `.env.example`.

## Запуск и обновление

```bash
docker compose build    # первый раз: клонирование репозитория и сборка образа
docker compose up -d
```

Логи:

```bash
docker compose logs -f
```

Остановка:

```bash
docker compose down
```

Данные VPN в `./awg-data` при обновлении образа обычно **сохраняются**; каталог не нужно удалять без необходимости.

## Массовое создание клиентов

После того как контейнер запущен и веб-интерфейс доступен:

1. Отредактируйте `clients.txt` (по одному имени на строку, `#` — комментарий).
2. Задайте пароль от панели и выполните скрипт (см. шапку `seed-clients.sh`):

   ```bash
   export ADMIN_PASSWORD='ваш_пароль_от_веб_UI'
   ./seed-clients.sh
   ```

По умолчанию UI на **`127.0.0.1`** — для скрипта на сервере ничего менять не нужно. С ПК при SSH-туннеле задайте `HOST=127.0.0.1` и свой локальный `PORT` (см. quickstart).

## Безопасность

- Не публикуйте `.env` и каталог `awg-data`.
- Веб-панель по умолчанию **не** слушает на внешнем интерфейсе; доступ — по SSH или с консоли сервера. Если измените `docker-compose.yml` и откроете `PORT` в интернет — дополнительно защищайте канал (фаервол, reverse proxy с TLS).
- Используйте устойчивый пароль для веб-UI; храните только **хэш** в `.env`.
