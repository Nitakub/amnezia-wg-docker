# AmneziaWG 3.1 + веб-интерфейс (Docker)

Ветка **`amnezia-wg-docker-v01`**: обвязка вокруг образа
**[myceliummesh/amneziawg-ui:3.1](https://hub.docker.com/r/myceliummesh/amneziawg-ui)** —
userspace AmneziaWG **3.1** (header protection + random trailers) и лёгкая веб-панель.

Ветка **`main`** в этом репозитории остаётся на стеке **AWG 2.0** (`awg-2.0-with-ui`) и этими изменениями не затрагивается.

Конспект миграции 2.0 → 3.1: [Habr](https://habr.com/ru/articles/1080342/).

## Быстрый старт

Пошагово — **[quickstart.md](quickstart.md)**.

## Требования

- **Docker** и **Docker Compose** (plugin `docker compose`).
- **`/dev/net/tun`**, capabilities `NET_ADMIN`, `SYS_MODULE` (см. `docker-compose.yml`).
- **VPN (UDP):** снаружи доступны хост и **`DEFAULT_PORT`** (проброс на роутере/фаерволе).
- **Веб-UI (TCP):** по умолчанию только **`127.0.0.1`** — в интернет не выставлен; доступ через **SSH port forwarding**.
- Клиенты: **AmneziaVPN ≥ 5.0.1.5** (или другой клиент с AWG 3.1). Профили 2.0 / обычный WireGuard **не подойдут**.

## Структура

| Файл / каталог | Назначение |
|----------------|------------|
| `docker-compose.yml` | Сервис `myceliummesh/amneziawg-ui:3.1`, порты, том |
| `.env.example` | Шаблон переменных (можно коммитить) |
| `.env` | Секреты и настройки (**не коммитить**) |
| `awg-data/` | Состояние панели и туннелей на хосте (**не коммитить**) |

## Конфигурация

1. `cp .env.example .env`
2. Сгенерируйте `WEB_UI_PASSWORD` (base64 от SHA-256 пароля) — см. `.env.example` / quickstart.
3. При необходимости смените `DEFAULT_PORT` (UDP VPN), `DEFAULT_MTU` (для 3.1 лучше **1280**), подсеть и DNS.

Параметры обфускации 3.1 (`HeaderProtectionKey`, `RandomTrailers`, `S1`–`S4` ≥ 12 и т.д.)
задаются **в панели при создании сервера**, а не списком `JC`/`H1`/`I1` как в ветке 2.0.

Старый `.env` от `main` (`WG_HOST`, `PASSWORD_HASH`, `JC`, `I1`–`I5`…) **этому образу не подходит**.

## Запуск

```bash
docker compose pull
docker compose up -d
```

Логи: `docker compose logs -f`  
Остановка: `docker compose down`

Каталог `./awg-data` при обновлении образа обычно сохраняется. **Не монтируйте сюда данные от AWG 2.0** — протокол другой, нужны новые сервер и клиенты.

## Миграция с AWG 2.0 (main / старый сервер)

1. Оставьте старый контейнер 2.0 работать (другой порт/имя), пока не раздадите ключи 3.1.
2. Поднимите этот стек на **чистом** `./awg-data` (или переименуйте старую папку).
3. В UI создайте сервер, раздайте новые конфиги.
4. Когда все перешли — остановите контейнер 2.0.

Включение header protection на «живом» конфиге 2.0 без перевыпуска клиентов оборвёт всех сразу.

## Что мы выяснили при настройке (грабли)

Краткий конспект реального развёртывания; детали шагов — в **[quickstart.md](quickstart.md)**.

### Сервер и Docker

| Проблема | Суть | Что делать |
|----------|------|------------|
| Старый `.env` / `awg-data` от 2.0 | Образ 3.1 их не понимает | Новый `.env` из `.env.example`, чистый `awg-data` |
| Порт в форме UI = `54844` | Дефолт панели ≠ проброс Docker | Порт сервера в UI = `DEFAULT_PORT` (часто **443**) |
| Веб-UI «не открывается» снаружи | В compose UI только на `127.0.0.1` | SSH: `-L WEB_UI_PORT:127.0.0.1:WEB_UI_PORT` |
| `I1`–`I5` в старом `.env` | В 3.1 обфускация сервера идёт из UI; I-пакеты — **у клиента** | Не копировать JC/H/I из 2.0; при создании клиента задать I1 при необходимости |
| Пустые `I2`–`I5` в старом образе 2.0 | `N-Rn00/awg-2.0-with-ui` подставлял случайный hex | В панели 3.1 пустые I2–I5 = пакеты не шлются (так и нужно) |
| Массовый seed через API 2.0 | awg-easy API здесь нет | Клиентов создавать только в UI |

### Обфускация и «маскировка под DNS»

- **3.1** сам включает header protection и random trailers при создании сервера — это не те же `JC`/`H1`–`H4` из 2.0.
- Сигнатурные пакеты **I1–I5** — клиентские: перед handshake уходит до пяти UDP-пакетов в CPS-синтаксисе (`<b 0x…>`, `<r N>`, …).
- Для вида «как DNS» достаточно **одного I1** (официальная сигнатура Amnezia); I2–I5 можно не заполнять.
- Порт **UDP 443** сам по себе не делает пакеты DNS — только номер порта; содержимое задаёт I1 (или дефолт сервера, часто QUIC-подобный).
- Проверка: в выданном клиенту `.conf` / в профиле AmneziaVPN должен быть нужный `I1`, а не случайный hex. Правка только серверного `.env` клиентский профиль не меняет.

### Клиенты

- Нужен **AmneziaVPN ≥ 5.0.1.5** (или иной клиент с AWG 3.1).
- Профили **Server 1 / Server 2** от стека 2.0 к серверу 3.1 **не подходят** — только новые `.conf` / QR с этой панели.
- После подключения (Linux): интерфейс `amn0` UP, пинг шлюза VPN (`10.x.x.1`), пинг `1.1.1.1`, внешний IP = IP VPN-сервера.

### Keenetic (Giga и др.)

| Прошивка | AmneziaWG 3.1 |
|----------|----------------|
| KeeneticOS **5.1.x** (стабильный канал) | Штатный импорт `.conf` 3.1 обычно **не работает** (нативно 2.0) |
| KeeneticOS **5.2+** | **Проверено:** `.conf` с этой панели импортируется штатно, туннель поднимается |
| Любая + Entware | Альтернатива: [AWG Manager](https://awgm.hoaxisr.ru/install/), режим **Kernel** |

На 5.2: компонент **WireGuard VPN** → **Интернет → Другие подключения → Загрузить из файла** → `.conf` клиента 3.1 → при необходимости политика выхода в интернет.

Конфиг 3.1 **нельзя** «downgrade» в 2.0 правкой файла — handshake не сойдётся.

## Безопасность

- Не публикуйте `.env` и `awg-data/`.
- Смените пароль UI (`changeme` из примера).
- Веб-панель по умолчанию только на localhost; наружу — только осознанно.
